# VRPTT benchmark instances (synthetic, Drexl-style)

## Source

The VRPTT test instances of Michael Drexl (raw milk collection, 109 instances in
the classes 2 2 4 - 8 8 8) were **never published for download**. They are only
described in:

> M. Drexl: "Branch-and-Cut Algorithms for the Vehicle Routing Problem with
> Trailers and Transshipments", Working Paper LM-2012-1210, Gutenberg School of
> Management and Economics, JGU Mainz, section 6.1.
> https://download.uni-mainz.de/RePEc/pdf/Discussion_Paper_1210.pdf

Therefore the files in this folder are **synthetic instances**, generated by
`generator/generate_instances.py` with fixed seeds, which reproduces the
generation recipe of the paper (section 6.1). They are NOT the original
instances, so no best-known or optimal objective values exist for them - the
benchmark spec reports absolute costs only and checks feasibility.

## Generation rules (per paper section 6.1)

- 100 x 100 km grid, depot in the centre (50, 50), Euclidean distances
  multiplied by a distance factor of 1.3 (folded into the variable costs).
- Supplies in [1000; 10000], loading time at customers 2 min per 1000 units.
- Transfer time 2 min per 1000 units of transferred supply; because the Phase 1
  MVP supports only a fixed transfer time, it is rounded to the expected mean
  transferred amount.
- Planning horizon 1320 min, non-restrictive time windows [0; 1320].
- Fleet per paper Table 1: lorry classes L1 (cap 10000, fix 180, 0.65/km) and
  L2 (cap 15000, fix 200, 0.70/km); trailer classes T1 (cap 10000, fix 20,
  0.04/km) and T2 (cap 15000, fix 25, 0.04/km).
- "x y z" instances: x customers (x/2 lorry customers, x/2 trailer customers),
  y = x transshipment locations (y/2 co-located with a trailer customer,
  y/2 pure), z vehicles (z/4 per class). Instance classes per paper Table 2:
  2 2 4 (30), 4 4 4 (20), 6 6 4 (10), 4 4 8 (7), 6 6 8 (23), 8 8 8 (19)
  = 109 instances.

## Deviations forced by the Phase 1 MVP

- Every trailer needs its own declared pulling lorry and at least one lorry
  must stay trailer-free (lorry customers are only servable by pure lorries).
  For z = 4 only the class-1 trailer is declared (pulled by the class-2
  lorry); for z = 8 only z/8 trailers per class are declared.
- The coupled lorry's capacity does not include the trailer capacity (Phase 1
  evaluates the pulling lorry with its own capacity only).
- The fleet count per class is not capped (enough vehicles "of each class such
  that the complete supply could be collected", as in the paper).

## File format

```
# comment lines
NAME <id>
HORIZON <minutes>
DEPOT <id> <x> <y>
CUSTOMER <id> <x> <y> <supply> <trailerAccessible 0|1> <serviceTime>
TL <id> <x> <y> <fixedTransferTime>
LORRY <id> <capacity> <fixCost> <varCostPerDistance>
TRAILER <id> <capacity> <fixCost> <varCostPerDistance> <pullingLorryId>
```

## Regeneration

```bash
python3 generator/generate_instances.py .
```
